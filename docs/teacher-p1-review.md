# Teacher P1 実装レビューとP2着手判定

2026-09-24。対象はWindows x64で使うTeacher CLIのP1全体。`TeacherContract`、`TeacherIdentity`、`TeacherTiming`、`TeacherAudio`、`TeacherDataset`、CLI、JSON Schema、回帰試験、1時間分の性能測定を確認した。P2は別schema 0.3へ分離した。

## 発見と修正

| 重要度 | 発見した問題 | 修正と確認 |
|---|---|---|
| High | JSONLの行長上限は`ReadLn`の後に検査されており、巨大な破損行を先にメモリへ読み込めた | 64 KiB内部バッファの`TBoundedLineReader`で読込み中に1 MiBを強制。過長行の拒否試験を追加 |
| High | P2拡張をschema 0.2のまま加えると、旧読込側が和文・変速をP1契約と区別しにくい | P1のschema 0.2を固定、P2をschema 0.3に分離。旧P1データを新検証器で再読込 |
| Medium | 26文字Base32の生成はあったが、逆変換と余剰ビットの検査がなかった | `SessionUUID`を追加。既知値・往復・不正文字・paddingを試験 |
| Medium | 実行名だけで起動すると相対的な`Argument(0)`で実行ファイルhashの取得に失敗する可能性があった | Windowsの実行モジュール絶対パスを取得する境界関数へ変更 |
| Medium | WPMを小数3桁へ丸めた後の許容誤差で、過剰桁をわずかに受理できた | 厳密な0.001 WPM表現との一致を要求し、20.0000000001を拒否 |

## 仕様との照合

| P1要求 | 判定と証拠 |
|---|---|
| 1:3:7と累積時刻 | 5～60 WPM、17.321 WPMと600文字の独立計算で一致。各境界の累積ドリフトなし |
| 波形・分割 | 立上り/立下りの独立数式、分割前後のPCM完全一致、全WAVバイトの内部再構成照合 |
| ID/命名 | UUID v4、Base32既知例、42/44文字、過長パス・同名衝突の拒否 |
| 正解・完了 | イベント/トークン参照、実音声とファイルハッシュ、完成manifestを最後に確定。破損・中断・注入した書込み失敗を拒否 |
| 旧形式 | 0.1→0.2移行でWAVの全バイトを維持。元の生成履歴がないことを明記。5速度と反復空白を試験 |
| 旧GUI | Windows GUIビルド、P0 exporterの回帰で既存動作を確認 |
| 性能 | 60秒分割の1時間分を最終バイナリで14.843秒、RTF 0.00412、観測ピーク9,474,048 bytes（約9.04 MiB）。開発PCでは目標RTF≤0.25、ピーク≤512 MiBを満たす |

生成器と検証器は時刻・レンダリングコアを共有するため、それだけで独立した正解証明とはしない。試験側には別実装の時刻式、符号固定表、PCM波形の数式、Python標準ライブラリのSHA-256を用いた。実受信音の正解はP1の範囲外。

レビュー後の判定: P1のWindows向け機能とオフライン性能は計画のG1条件を満たす。測定バイナリSHA-256は`9ccd5a62e555d58045ecb88aefa2ec563af228278bdc67f08405a97faa4be583`、環境はWindows 10.0.26200、Intel Family 6 Model 170、18 logical processors。測定は25 ms間隔のworking set観測であり、N150実機・実時間入力の耐久性・モデル復号精度は別ゲートで検証する。
